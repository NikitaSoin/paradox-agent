## 1. Устройство репозитория — читать до первого git-коммита

🔴 **Эта папка физически лежит ВНУТРИ другого проекта** —
`/Users/soinnikita/investment-platform/` (платформа Basis, `github.com/NikitaSoin/Basis`).
Но это **самостоятельный репозиторий** со своим `.git`, своей историей и своим remote.

Что из этого следует:

- **Все команды git выполняй, находясь внутри `AI-agent_paradox/`.** Если запустить
  `git status` уровнем выше — попадёшь в репозиторий Basis, это чужой проект с боевым
  сайтом. Проверка перед работой:
  ```bash
  git rev-parse --show-toplevel     # должно оканчиваться на /AI-agent_paradox
  git remote -v                     # должно быть paradox-agent, НЕ Basis
  ```
- **Никогда не коммить эту папку в Basis.** Она там не отслеживается (0 файлов в индексе).
  У Basis есть правило: репозиторий — расходный ресурс деплоя, туда уже один раз попало
  лишнее и деплой стал падать на клонировании. 49 МБ этой папки повторят историю.
  Для защиты она внесена в `.gitignore` Basis.
- Веток одна — `main`. Remote один — `origin`.

### Как пушить

```bash
cd /Users/soinnikita/investment-platform/AI-agent_paradox
git status                 # убедись, что .env и архивов в списке НЕТ
git add -A
git commit -m "…"
git push origin main
```

Доступ к GitHub — через системную связку ключей macOS (`osxkeychain`), логин `NikitaSoin`.
Отдельный токен вводить не нужно, `git push` работает сам. Утилиты `gh` на машине нет.

### Что в репозиторий НЕ попадает (и почему)

| Не входит | Причина |
|---|---|
| `app/.env` | **реальные ключи**. Задаются в панели хостинга |
| `node_modules/` | 33 МБ, ставится на сервере командой `npm install` |
| `archive/`, `extracted/` | исходные материалы СКОЛКОВО, ~8 МБ. Приложению для работы не нужны, плюс это чужие документы с именами людей |
| `*.zip` | `drive-download-*.zip` (7,3 МБ) и сборки `paradox-agent*.zip` |
| `app/start.command`, `start.bat`, `share.command` | локальные запускалки «дважды кликнуть» |

Всё это остаётся на диске, просто не уезжает в GitHub. Правила — в `.gitignore`.

**Что входит обязательно:** `app/kb/` — продуктовая база знаний (34 парадокса, кейсы,
паспорта). Без неё приложение не соберёт разбор.

Итого в репозитории 25 файлов, ~300 КБ.

## 2. Что настроено в самом приложении для публикации

Приложение написано на встроенном `node:http`, **без фреймворка** (ни Express, ни Nest,
ни Fastify, ни Hapi — их в коде нет).

### Две точки входа — намеренно

Панель хостинга просит выбрать «тип приложения» из списка фреймворков и под каждый
подставляет свою команду запуска: чаще `node index.js`, иногда `npm start`. Поэтому
в репозитории есть обе дороги, и обе ведут в `app/server.mjs`:

| Откуда запускают | Что срабатывает |
|---|---|
| корень, `npm start` | корневой `package.json` → `node app/server.mjs` |
| корень, `node index.js` | `index.js` → `import "./app/server.mjs"` |
| папка `app`, `npm start` | `app/package.json` → `node server.mjs` |

Все три проверены — отвечают. Своей логики в `index.js` нет и быть не должно.

### Доступ по коду

Переменная `ACCESS_CODE`. Если задана — сайт закрыт, и войти можно тремя способами:

1. **Ссылка `https://<адрес>/?code=<код>`** — основной. Её можно переслать участнику.
   Код запоминается в cookie на 7 дней и **убирается из адресной строки**, чтобы не
   уехал дальше чьим-нибудь скриншотом.
2. Cookie `pa_access` — чтобы код не спрашивался при каждой перезагрузке.
3. Basic-авторизация (`curl -u ":код"`) — для проверок из терминала.

Если `ACCESS_CODE` пуст — **сайт открыт всем, кто знает адрес**. Это допустимо только
в демо-режиме (без ключей): тратить там нечего.

🔴 История: в `.env` код был записан с опечаткой — `ACCEASS_CODE` вместо `ACCESS_CODE`.
Программа такую переменную не видит, и защита не работала вовсе. Исправлено 2026-08-24.
При правке `.env` или переменных в панели **сверяй имена буква в букву**.

### Проверка живости `/healthz`

Открытый адрес, отвечает `200 ok`, кода доступа не требует, ничего о системе не
раскрывает. Нужен вот зачем: хостинг периодически пингует приложение. Если пинговать `/`
при заданном коде доступа, он получит `401`, решит, что приложение упало, и уйдёт
в перезапуск по кругу. В настройках health check указывать **`/healthz`**.

### Запрет индексации

Тройной: заголовок `X-Robots-Tag: noindex, nofollow, noarchive` на каждом ответе,
`robots.txt` с `Disallow: /`, метка `<meta name="robots">` в самой странице.
Страница служебная, в поиске ей делать нечего.

### Демо-режим

Без ключей провайдера приложение **само** уходит в демо: проигрывает записанный разбор
(`app/mock.mjs`), модель не вызывает, денег не тратит. Виден по пометке в интерфейсе.
Это штатный режим, а не поломка — им удобно давать людям потыкать интерфейс.

## 3. Timeweb Cloud — что создавать

**Облачные приложения → Создать приложение → вкладка «Бэкенд» → Node.js.**
НЕ «Фронтенд» и НЕ «Статический сайт»: приложение должно держать процесс, потому что
ключ живёт на сервере и ответ модели стримится в браузер (SSE).

| Поле | Значение |
|---|---|
| Фреймворк из списка | **Express** (или любой) — выбор лишь подставляет команды по умолчанию, мы их задаём сами |
| Версия Node.js | 20 или новее |
| Источник | GitHub → `NikitaSoin/paradox-agent`, ветка `main` |
| Директория | `./` (панель может не принимать одиночный `/`). Если требует имя папки — **`app`**, это тоже рабочий вариант |
| Команда сборки | `npm install` |
| Команда запуска | `npm start` |
| Порт | не задавать — приложение берёт `PORT`, который выдаёт платформа |
| Health check | `/healthz` |
| Автодеплой при push | включить |

**Ресурсы:** младший тариф (1 ядро / 1 ГБ) с запасом. Приложение почти ничего не считает —
вся работа на стороне модели. База данных, объектное хранилище, воркеры, бэкапы —
**не нужны**: приложение ничего не хранит, разбор живёт в браузере участника,
база знаний лежит файлами в репозитории.

**Домен:** достаточно выданного Timeweb — он длинный и неугадываемый, это и требуется.
Свой поддомен (например `paradox.inbasis.ru`) можно прицепить позже.

### Переменные окружения

Задаются **в панели**, в репозиторий не попадают. Значения — в локальном `app/.env`.

| Переменная | Зачем | Обязательна |
|---|---|---|
| `ACCESS_CODE` | код доступа | 🔴 да, как только появился ключ |
| `ANTHROPIC_API_KEY` | живой режим на Claude | нет — без неё демо |
| `ANTHROPIC_BASE_URL` | шлюз, если прямой доступ к `api.anthropic.com` закрыт | скорее всего да, см. ниже |
| `DEEPSEEK_API_KEY` | запасной провайдер, дешевле | нет |
| `DEEPSEEK_BASE_URL` | шлюз для DeepSeek | по ситуации |
| `PROVIDER` | `anthropic` или `deepseek` | нет |

🔴 **`PORT` не задавать.** Его выдаёт платформа; заданный вручную посадит приложение
не на тот порт, и снаружи это выглядит как «не отвечает».

### Порядок выкатки, который выбран сознательно

1. Первый деплой — **без переменных вообще**. Приложение поднимется в демо-режиме.
   Убеждаемся, что сборка проходит и сайт открывается.
2. Потом — `ACCESS_CODE` **и** ключ, вместе. Ключ без кода доступа выставлять нельзя:
   ссылка у кого-то останется, и баланс будут тратить незнакомые люди.
3. Если живой режим молчит — см. следующий пункт.

⚠️ **Доступ из дата-центра.** У соседнего проекта на этом же хостинге исходящий TLS до
`api.deepseek.com` резался: TCP проходил, рукопожатие отваливалось по таймауту, при том
что с ноутбука всё работало. Лечилось шлюзом-ретранслятором через `*_BASE_URL`.
`api.anthropic.com` из российского ЦОД, скорее всего, тоже недоступен напрямую.
Если локально работает, а на хостинге таймаут — **это сеть, а не код**, не переписывай
`agent.mjs`. В `app/.env` адреса шлюзов уже прописаны, их и надо перенести в панель.

## 4. Проверка после деплоя

```bash
curl -s -o /dev/null -w "healthz  %{http_code}\n" https://<адрес>/healthz   # 200
curl -s -o /dev/null -w "корень   %{http_code}\n" https://<адрес>/          # 401 при заданном коде, 200 без него
curl -s https://<адрес>/robots.txt                                          # Disallow: /
curl -s -D - -o /dev/null https://<адрес>/healthz | grep -i x-robots        # noindex
```

Затем открыть `https://<адрес>/?code=<код>` в браузере и пройти **один разбор целиком**.
Проверка курлом говорит только «сервер отвечает» — она не говорит, что разбор
собирается. Демо-режим виден по пометке в интерфейсе, живой — по названию модели.

## 5. Локальный запуск

```bash
cd app && npm install && npm start        # откроется на http://localhost:5173
```

Порт и код можно переопределить: `PORT=5999 ACCESS_CODE=test npm start`.
Переменные окружения имеют приоритет над `app/.env` — файл не перетирает то, что уже
задано в среде.
