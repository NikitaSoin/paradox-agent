# AI-agent_paradox

ИИ-инструмент для CEO/собственников: помогает различать тип управленческого вызова
(**проблема / дилемма / парадокс**) и работать с вызовом типа «парадокс».

> 🔴 **Про git, GitHub и хостинг — читай `ПУБЛИКАЦИЯ.md`, там всё.** Коротко: эта папка
> (`~/AI-agent_paradox`) и есть рабочая копия репозитория
> `github.com/NikitaSoin/paradox-agent`, ветка `main`. Правим здесь, отсюда же пушим:
> `git add -A && git commit -m "…" && git push`.
> Ключи (`app/.env`) в репозиторий не уезжают — на хостинге они задаются переменными
> окружения в панели. Исходные материалы (`archive/`, `extracted/`, `prototype/`, zip-архивы)
> тоже исключены: они нужны локально, но приложению для работы не требуются.

Заказчик — Школа управления СКОЛКОВО. Язык продукта и документации — **русский**.

## Роли в этом репозитории

Пользователь (Никита Соин) выступает как **продакт-оунер / гендир**: ставит задачи,
принимает решения о продукте. Разработка, дизайн, аналитика — на Claude.

Правила работы:
- **Не галлюцинировать.** Любое утверждение о содержании материалов, кейсах, авторах
  и источниках должно быть проверяемо по `archive/` или `extracted/`. Если факта нет
  в архиве — так и говорить, а не додумывать.
- **Сложные интеллектуальные развилки** — выносить на субагента-советника на модели
  `fable` (свежий взгляд), потом принимать решение самому.
- В архиве много устаревших и побочных материалов (планы эфира, приглашения,
  расписания). Если материал не относится к делу — пропускать.

## Структура репозитория

```
drive-download-*.zip     исходный архив с Google Drive (не трогать)
archive/                 распакованный архив, исходные файлы
extracted/               машиночитаемый текст, извлечённый из архива
  *.txt                    текст из .docx / .pptx / .pdf
  html/*.txt               видимый текст из HTML-прототипов
  paradox_table_v3.json    50 парадоксов, распарсенные из таблицы v3
CLAUDE.md                этот файл
```

Архив распаковывается только через Python (`zipfile`) — `unzip` ломается на
кириллических именах в этой файловой системе.

## Ключевая содержательная модель

Она собрана из нескольких документов и должна оставаться консистентной в продукте.

### Три типа вызова

| Тип | Что значит «решить» | Ошибка диагноза |
|---|---|---|
| **Проблема** | устранить | принята за парадокс → «рационализованная пассивность» |
| **Дилемма** | выбрать сторону | принята за парадокс → паралич, сидение на двух стульях |
| **Парадокс** | удерживать натяжение | принят за проблему → бег по кругу, выгорание; принят за дилемму → мина замедленного действия, сбой через 2–3 года |

В `paradox-dilemma-problem-focused_v2ET.html` добавлен **4-й тип — диалектическое
противоречие** (снимается через Aufhebung/развитие). В ТЗ его нет. Это открытая развилка.

### Критерии парадокса (4+2)

Про ситуацию: **структурный** (необходимый — два правомерных взаимоисключающих полюса),
**экономический** (любой выбор ведёт к потерям).
Про людей: **политический** (сильные «партии» за каждый полюс), **эмоциональный**
(сигнальный, не определяющий — острая защита, тревога, поиск внешнего виноватого).
Отличают парадокс от дилеммы: **неизмеримость** полюсов и **цикличность** (возвращается снова).

### Четыре подхода к работе с парадоксом (по ТЗ)

1. **Выход в надсистему** — сверхцель, система координат более высокого уровня
2. **Дробление вниз** — до уровня дилеммы или проблемы
3. **Разнесение** в пространстве / во времени
4. **Синтез** — ТРИЗ/SIT: убрать полярность, разнести функцию и носитель, умножение элементов

В более ранних материалах подходов три (без «выхода в надсистему» и «дробления»);
**четыре — актуальная версия из ТЗ**.

### Алгоритм из эфира

**Диагноз** (это вообще парадокс?) → **Настройка**, один раз (назвать полюса через то, что
они дают + тест легитимности; развернуть карту 4 квадрантов; поставить ранние сигналы
с корректировками, 2–3 на полюс; задать ритм и держателя) → **Цикл**, постоянно.

### Две позиции

- **Позиция I — смирение и мудрость.** Парадокс структурен, с ним живут. Карта — постоянная архитектура.
- **Позиция II — поиск и работа.** Парадокс смертен, это признак недостроенного мышления. Карта — временные строительные леса, параллельно ищется концепт для растворения.

Обе легитимны и имеют традицию от античности. Продукт не должен молча выбирать одну.

## Ограничения продукта (из ТЗ, обязательны к соблюдению)

- Инструмент **не ставит диагноз за пользователя** — тип вызова во многом субъективен;
  инструмент помогает об этом думать.
- Цикл работы — **максимум 5–7 минут**.
- **Минимум ввода текста**, выбор из вариантов предпочтителен.
- **Конфиденциальность**: вопросы не должны отпугивать.
- По подходам — **примеры и вопросы к себе, а не готовые решения**.
- Подтягивание контекста из открытых источников — интересно, но не приоритет.

## Работа с материалами

Пере-извлечь текст из архива:

```bash
python3 -c "
import zipfile, os
z = zipfile.ZipFile('drive-download-20260822T145816Z-1-001.zip')
for i in z.infolist():
    if i.is_dir(): continue
    p = os.path.join('archive', i.filename)
    os.makedirs(os.path.dirname(p), exist_ok=True)
    open(p,'wb').write(z.read(i))
"
```

`.docx` читается через `python-docx`, `.pdf` — через `pdftotext -layout`,
`.pptx` — парсингом `ppt/slides/slideN.xml` (модуля `python-pptx` нет).
HTML-прототипы — самодостаточные одностраничники, содержательны и как контент,
и как ориентир по визуальному языку.
