# Как выложить тренажёр в сеть (Timeweb Cloud)

Приложение — **живой сервер на Node.js**, а не набор статических страниц: оно держит
ключ провайдера у себя и стримит ответ модели в браузер. Поэтому на хостинге выбирается
тип «бэкенд», а не «фронтенд/статика».

## 1. Что создать в панели Timeweb

**Облачные приложения → Создать приложение**

| Поле | Значение |
|---|---|
| Тип приложения | **Бэкенд → Node.js** (НЕ «Фронтенд», НЕ «Статический сайт») |
| Версия Node.js | 20 или новее |
| Источник | GitHub → репозиторий `paradox-agent`, ветка `main` |
| Директория проекта | `/` (корень — в нём лежит `package.json`) |
| Команда сборки | `npm install` |
| Команда запуска | `npm start` |
| Порт | оставить по умолчанию — приложение само слушает тот порт, который передаёт платформа (`PORT`) |
| Проверка доступности (health check) | путь `/healthz` |

🔴 **Про health check.** Если платформа проверяет живость запросом на `/`, а код доступа
задан, она получит `401` и может решить, что приложение упало, — и уйдёт в перезапуск по
кругу. Поэтому в приложении есть отдельный открытый адрес `/healthz`, он всегда отвечает
`200 ok`. Если поле для пути проверки в панели есть — указать `/healthz`.

## 2. Переменные окружения

Задаются **в панели**, в репозиторий не попадают (файл `.env` в `.gitignore`).

| Переменная | Зачем | Обязательна |
|---|---|---|
| `ACCESS_CODE` | код доступа к сайту | 🔴 да, если есть ключ провайдера |
| `ANTHROPIC_API_KEY` | живой режим на Claude | нет — без неё демо-режим |
| `ANTHROPIC_BASE_URL` | свой шлюз, если прямой доступ к `api.anthropic.com` из ЦОД закрыт | по ситуации |
| `DEEPSEEK_API_KEY` | запасной провайдер, дешевле | нет |
| `DEEPSEEK_BASE_URL` | шлюз для DeepSeek | по ситуации |
| `PROVIDER` | `anthropic` или `deepseek` — чем считать | нет |

**Без ключей приложение работает в демо-режиме**: сценарий проигрывается на записанном
разборе, модель не вызывается, денег не тратит. Хороший способ дать людям потыкать
интерфейс, ничем не рискуя.

⚠️ **Про доступ из дата-центра.** У соседнего проекта (Basis) на этом же хостинге исходящий
TLS до `api.deepseek.com` и FRED резался — TCP проходил, а рукопожатие отваливалось по
таймауту, при том что с ноутбука всё работало. Лечилось шлюзом-ретранслятором
(`*_BASE_URL`). Если живой режим молчит или падает по таймауту, а локально работает —
причина, скорее всего, эта, а не код.

## 3. Как пускать людей

Ссылка для участника: `https://<адрес>/?code=<ACCESS_CODE>`

Код из адреса запоминается в cookie на 7 дней и убирается из адресной строки, чтобы не
уехал дальше случайным скриншотом. Всплывающего окна с паролем участник не видит.

Страница закрыта от поисковиков дважды: заголовком `X-Robots-Tag: noindex` на каждом
ответе и `robots.txt` с `Disallow: /`.

## 4. Что стоит проверить после первого деплоя

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<адрес>/healthz     # ждём 200
curl -s -o /dev/null -w "%{http_code}\n" https://<адрес>/            # ждём 401 — код работает
curl -s https://<адрес>/robots.txt                                   # ждём Disallow: /
```

Затем открыть `https://<адрес>/?code=<код>` в браузере и пройти один разбор целиком:
демо-режим виден по пометке в интерфейсе, живой — по названию модели.

## 5. Чего в репозитории нет намеренно

`archive/`, `extracted/`, исходные `.zip` с материалами СКОЛКОВО и `node_modules`.
Приложению для работы они не нужны, а в репозитории от них только вес (~15 МБ) и лишняя
копия чужих документов с именами людей. Всё это остаётся локально. Продуктовая база
знаний (34 парадокса, кейсы, паспорта) лежит в `app/kb/` и в репозитории **есть** —
без неё приложение не соберёт разбор.
