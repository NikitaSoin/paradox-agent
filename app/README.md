# Карта натяжения

Сайт с ИИ-агентом: помогает CEO различить тип управленческого вызова
(**проблема / дилемма / парадокс**) и работать с вызовом типа «парадокс».
Разработка для Школы управления СКОЛКОВО.

## Запуск

Двойной клик по **`start.command`** — поставит зависимости при первом запуске,
освободит порт, поднимет сервер и откроет браузер. Окно терминала не закрывать:
пока оно открыто, сайт работает.

Или руками:

```bash
cd app
npm install
cp .env.example .env      # вписать ключи
npm start                 # http://localhost:5173
```

Без ключа сайт поднимется в **демо-режиме**: весь сценарий проигрывается
на заранее записанном разборе, модель не вызывается. Пригодится, если на
площадке нет сети — и чтобы показывать интерфейс, не тратя токены.

```bash
npm test                  # прогон всего сценария в jsdom, без сети
```

## Передать другому человеку

```bash
npm run pack          # архив без ключей — получатель вписывает свои
npm run pack:keys     # архив с вашим .env — получатель просто запускает
```

`pack:keys` кладёт в архив рабочие ключи: получатель сможет тратить ваш бюджет,
поэтому не выкладывайте такой архив в общий доступ. Внутрь добавляется
`ПРОЧТИ_МЕНЯ.txt` с этим же предупреждением. Обычный `pack` физически проверяет,
что `.env` в сборку не попал, и отказывается собираться, если попал.

В обоих случаях `node_modules` не кладётся — получатель ставит зависимости сам
(это делает `start.command` / `start.bat` при первом запуске).

**Что нужно получателю:** Node.js 18 или новее и интернет для `npm install`.
Больше ничего — сборки нет, фреймворков нет, база данных не нужна.

## Что где

```
app/
  server.mjs        бэкенд: статика + POST /api/step (SSE) + /api/theory, /api/config
  agent.mjs         агент: схемы структурированного вывода, промпты, вызов модели
  mock.mjs          демо-режим — записанный разбор одного кейса
  theory.mjs        сборка справочника для вкладки «Теория»
  kb/
    kb.mjs            база знаний + рендер в системный промпт
    paradoxes34.json  34 организационных парадокса с первоисточниками
    passports.json    6 полных паспортов по сетке из 11 параметров
    cases.json        29 кейсов с фактурой
  public/
    index.html app.js styles.css   фронтенд, без сборки и без зависимостей
  test-flow.mjs     headless-прогон всего сценария
```

Фронтенд — обычные статические файлы: ни сборки, ни фреймворка, ни npm-зависимостей.
Их можно вынести на любой хостинг, оставив бэкенд отдельно; связь только через
три HTTP-эндпоинта. Бэкенд — один файл на стандартной библиотеке Node плюс SDK Anthropic.

## История и тема

**История разборов** — вкладка в сайдбаре. Каждый прогон сохраняется автоматически,
начиная с первого чтения ситуации, и обновляется на каждом шаге. Незавершённый разбор
тоже сохраняется: к нему можно вернуться и допройти с того места, где остановились.
Записи открываются по клику, удаляются по одной или все сразу.

Разбор можно **отложить в любой момент** — кнопка «Отложить и начать новый разбор» на каждом
шаге. Текущий сохраняется на том шаге, где вы остановились, помечается в списке как
незавершённый, и открывается экран ввода под новый кейс. Из уведомления о сохранении
можно сразу перейти к отложенной записи.

Хранение — `localStorage` браузера, ключ `paradox.history.v1`, до 50 записей.
**На сервер история не уходит.** Единственное, что покидает браузер, — описание ситуации
и ответы на вопросы, и только внутри вызова модели для конкретного шага.

**Тема** — переключатель «Авто / Светлая / Тёмная» внизу сайдбара, выбор запоминается
(`paradox.theme`). «Авто» следует системной настройке. Тема ставится инлайн-скриптом
до первой отрисовки, поэтому при загрузке не мигает.

## Как устроен агент

Модель — `claude-opus-5`, адаптивное мышление, effort `high`,
структурированный вывод по JSON-схеме на каждом шаге, потоковая передача
резюме рассуждения в интерфейс. База знаний (~17 тысяч токенов) уходит
в системный промпт под кэшем, поэтому со второго вызова она почти бесплатна.

Четыре шага, каждый — отдельный вызов со своей схемой:

| Шаг | Что делает |
|---|---|
| `read` | Читает описание, определяет сегмент пользователя и позицию (удержание или поиск), выдвигает гипотезу о типе вызова, оценивает шесть критериев, предлагает оси, **генерирует вопросы под конкретный кейс** |
| `refine` | Уточняет гипотезу по ответам, разворачивает три прочтения ситуации, заполняет оси по сетке из 11 параметров, оценивает положение на оси и наличие оптимума, подбирает кейсы |
| `decide_paradox` | Разбирает четыре подхода применительно к оси, даёт вопросы к себе, первые шаги, кейс-близнец, рекомендацию и ранний сигнал перекоса |
| `decide_problem` / `decide_dilemma` | Рабочий разбор для тех, кто назвал вызов иначе. Ни одна ветка не тупик |

Число вопросов агент выбирает сам: если по описанию явно проблема — одного-двух
хватит; если признаки противоречат друг другу — до шести.

## Правила, зашитые в агента

- Не ставит диагноз за пользователя. Выдаёт гипотезу с основаниями; называет человек.
- Опирается только на базу знаний. Кейсы, компании, цифры и источники не выдумывает.
- Своя ось — нормально: если натяжение не совпадает ни с одним парадоксом из библиотеки,
  агент формулирует собственную. Осей может быть несколько.
- Не просит названий компаний, имён и цифр.
- Осторожность касается только называния типа вызова; всё остальное формулируется прямо.
