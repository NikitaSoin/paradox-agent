# Техническая база для нового проекта

> **Как пользоваться.** Скопируйте этот файл в папку нового проекта первым делом
> и скажите ИИ: «читай `СТАРТ_НОВОГО_ПРОЕКТА.md`, работаем по нему». Здесь собрано
> всё, что уже проверено на боевом проекте — чтобы не изобретать заново и не
> наступать второй раз на те же грабли. Всё, что помечено 🔴, стоило нам времени.
>
> Файл про **техническую основу**, а не про продукт. Продуктовые решения —
> в `CLAUDE.md` конкретного проекта.

## 0. Быстрый старт — одной командой

```bash
~/AI-agent_paradox/новый-проект.sh имя-проекта "Одно предложение о проекте"
```

Скрипт создаёт папку, кладёт эту инструкцию и заготовку `CLAUDE.md`, скелет
приложения, `.gitignore`, точку входа для хостинга; подставляет ключи из локального
хранилища; делает первый коммит, **проверяет, что `.env` в него не попал**, и
создаёт приватный репозиторий на GitHub с первым пушем.

**Никакой отдельной авторизации не требуется.** Доступ к GitHub уже сохранён в
связке ключей macOS — тот самый, которым работает обычный `git push`. Скрипт берёт
его оттуда и создаёт репозиторий через API. Проверить, что доступ на месте:

```bash
printf "protocol=https\nhost=github.com\n\n" | git credential fill
```

Если выводит `username=…` и `password=…` — всё готово. `gh auth login` **не нужен**:
это отдельная авторизация отдельной утилиты, к работе с git она отношения не имеет.

🔴 **Имя проекта — только латиница, цифры и дефис.** GitHub выбрасывает из имени
репозитория всё нелатинское: `мой-проект` превратится в `-----`. Скрипт это
проверяет и не даст создать такой репозиторий.

Дальше в новой папке достаточно сказать ИИ: «читай `СТАРТ_НОВОГО_ПРОЕКТА.md`,
работаем по нему».

### Где лежат ключи

🔴 **Ключи не хранятся в репозиториях — ни в одном, даже приватном.** У GitHub есть
автоматическое сканирование секретов в партнёрстве с Anthropic: ключ, попавший
в репозиторий, детектится и **отзывается автоматически**. Плюс история git постоянна —
удалить ключ потом означает переписывать историю.

Единое хранилище на машине:

```
~/.config/ai-projects/keys.env      права 600, вне всех репозиториев
```

Новый проект копирует его в свой `app/.env` (который в `.gitignore`). Меняется ключ —
меняете в одном месте. На хостинге ключи задаются переменными окружения в панели,
файл туда не едет.

## 1. С чего начать: папка и репозиторий

🔴 **Главное правило: папка, в которой работаете, и есть репозиторий.** Не заводите
рабочую копию в одном месте, а репозиторий в другом — рано или поздно они разъедутся,
и придётся вручную переносить файлы туда-сюда. Один проект — одна папка — один `.git`.

Не создавайте папку проекта внутри другого проекта. Вложенный `.git` работает, но
любая команда, запущенная уровнем выше, попадёт в чужой репозиторий.

**Ровно так был заведён репозиторий этого проекта** — шесть шагов, вручную,
без всяких утилит:

```bash
# 1. Папка проекта
mkdir ~/имя-проекта && cd ~/имя-проекта

# 2. Сначала .gitignore — ДО первого add, чтобы ключи физически не смогли попасть
#    (содержимое — ниже в этом разделе)

# 3. Репозиторий
git init
git branch -M main

# 4. Пустой приватный репозиторий создать руками на github.com:
#    New repository → имя → Private → БЕЗ readme/gitignore/лицензии → Create
git remote add origin https://github.com/ВАШ_ЛОГИН/имя-репозитория.git

# 5. Проверить, что уезжает, и только потом коммитить
git add -A
git status                     # 🔴 .env, node_modules, архивов в списке быть не должно
git commit -m "Первый коммит"

# 6. Отправить
git push -u origin main
```

Дальше каждый раз: `git add -A && git commit -m "…" && git push`.

Доступ к GitHub — через системную связку ключей macOS (`osxkeychain`), логин
запоминается при первом пуше. Отдельный токен вводить не нужно.

Если установлен `gh` (`gh auth login` один раз), шаг 4 не нужен — репозиторий
создаётся из терминала:

```bash
gh repo create имя-репозитория --private --source=. --remote=origin --push
```

**Проверка перед первым коммитом** (10 секунд, экономит часы):

```bash
git rev-parse --show-toplevel   # должно быть именно вашей папкой
git remote -v                   # должен быть нужный репозиторий
git status                      # .env и архивов в списке быть НЕ должно
```

### `.gitignore` — берите этот целиком

```gitignore
# Ключи — НИКОГДА в репозиторий. На хостинге задаются переменными окружения.
.env
.env.local
app/.env

# Ставится на сервере при сборке
node_modules/

# Исходные материалы, архивы, выгрузки — нужны локально, приложению не нужны
archive/

# Локальные запускалки «дважды кликнуть»
*.command

```

### Ежедневная работа

Ветка одна — `main`. Для проекта, который ведёт один человек с ИИ, ветки и
pull request'ы дают только накладные расходы.

```bash
git status                 # что изменилось
git diff                   # что именно изменилось в коде
git add -A
git commit -m "Что сделано и зачем"
git push
```

**Перед пушем — три проверки** (те же, что перед первым коммитом):

```bash
git status --porcelain          # 🔴 .env в списке быть не должно
git diff --cached | grep -iE "sk-ant|api03|Bearer |password"   # пусто = хорошо
git log --oneline -1            # тот ли коммит уезжает
```

**Убедиться, что локально и на GitHub одно и то же:**

```bash
git fetch origin
git rev-parse HEAD origin/main  # два одинаковых хеша = всё синхронно
git status                      # «nothing to commit, working tree clean»
```

**Сообщения к коммитам.** Первая строка — что изменилось для пользователя, не для
файла: «Просмотр записей в истории» лучше, чем «правки в app.js». Если правка
неочевидная — абзацем ниже объяснить, почему так, а не иначе. Через полгода это
единственное, что останется от ваших рассуждений.

### Если что-то пошло не так

**🔴 Ключ случайно закоммичен.** Порядок именно такой:

1. **Сразу перевыпустить ключ** в кабинете провайдера. Это единственное настоящее
   лечение: всё, что попало в git, считается скомпрометированным, даже если вы
   тут же всё удалили.
2. Если коммит **ещё не запушен** — откатить и пересобрать:
   ```bash
   git reset --soft HEAD~1        # коммит убрали, файлы на месте
   # добавить файл в .gitignore, затем:
   git rm --cached app/.env
   git commit -m "…"
   ```
3. Если уже запушен — вычистить из истории (`git filter-repo` или BFG) и сделать
   force-push. Но пункт 1 всё равно обязателен: ключ уже уехал.

**Файл попал в git до того, как его добавили в `.gitignore`.** `.gitignore`
действует только на неотслеживаемые файлы — уже добавленный он не выкинет:

```bash
git rm --cached путь/к/файлу     # убрать из git, оставить на диске
git commit -m "Файл больше не отслеживается"
```

**Пуш отклонён («updates were rejected»)** — на GitHub есть коммиты, которых нет
у вас (правили с другой машины или через веб):

```bash
git pull --rebase origin main    # подложить свои поверх чужих
git push
```

**Отменить последний коммит, но сохранить правки:** `git reset --soft HEAD~1`
**Вернуть файл к последнему коммиту:** `git checkout -- путь/к/файлу`
**Посмотреть, что уедет при пуше:** `git log origin/main..HEAD --oneline`

**🔴 Рабочая папка и репозиторий разъехались** (правите в одном месте, а `.git`
живёт в другом — так у нас и вышло). Лечится подключением папки к репозиторию
без потери файлов:

```bash
cd ~/рабочая-папка
git init                                   # если .git ещё нет
git remote add origin https://github.com/ВАШ_ЛОГИН/репозиторий.git
git fetch origin
git reset origin/main                      # 🔴 без --hard: файлы на диске не тронутся
git status                                 # теперь видно, чем папка отличается от репозитория
# забрать из репозитория то, чего локально нет или что там новее:
git checkout origin/main -- .gitignore путь/к/нужным/файлам
```

**Восстановить проект на другой машине:**

```bash
git clone https://github.com/ВАШ_ЛОГИН/репозиторий.git
cd репозиторий && npm install
cp ~/.config/ai-projects/keys.env app/.env    # ключи в git не приезжают
npm start
```

## 2. `CLAUDE.md` проекта — что писать

Это файл, который ИИ читает первым в каждой сессии. Он окупается: без него каждый
разговор начинается с объяснения одного и того же.

**Класть надо:**

- одно предложение о том, что за продукт и для кого;
- кто заказчик, на каком языке продукт и документация;
- **роли**: кто вы в этом проекте (например, «ставлю задачи и принимаю продуктовые
  решения, разработка на ИИ») — это сильно меняет манеру работы;
- правила работы: чего нельзя (например, «не выдумывать факты, любое утверждение
  должно быть проверяемо по материалам в `archive/`»);
- структуру папок с одной строкой пояснения на каждую;
- ключевые содержательные модели продукта — то, что должно оставаться
  консистентным и не переизобретаться в каждой правке;
- ограничения продукта, которые нельзя нарушать;
- ссылку на файл про деплой (см. ниже), а не сам деплой.

**Класть не надо:** то, что видно из кода; историю правок (для этого git); длинные
куски кода — они устареют молча.

**Шаблон:**

```markdown
# Название проекта

Одно предложение: что это и для кого.
Заказчик — …. Язык продукта и документации — русский.

> 🔴 Про git, GitHub и хостинг — читай `ПУБЛИКАЦИЯ.md`.
> Эта папка и есть рабочая копия репозитория `github.com/…`, ветка `main`.
> Правим здесь, отсюда же пушим. Ключи (`app/.env`) в репозиторий не уезжают.

## Роли
Пользователь — продакт-оунер: ставит задачи, принимает решения о продукте.
Разработка, дизайн, аналитика — на ИИ.

Правила работы:
- Не галлюцинировать: любое утверждение о материалах проверяемо по `archive/`.
  Если факта нет — так и сказать, а не додумать.
- Сложные развилки — выносить на отдельного советника, потом решать самому.

## Структура репозитория
… (по строке на папку)

## Ключевые модели продукта
… (то, что должно оставаться консистентным)

## Ограничения
… (что нельзя нарушать)
```

## 3. Ключи и `.env`

🔴 **Ключ не должен попадать: в репозиторий, в чат, в скриншот, в архив для передачи.**
Если ключ где-то засветился — перевыпустите его, это две минуты.

Три файла:

| Файл | Что в нём | В git |
|---|---|---|
| `app/.env` | настоящие ключи | **нет** |
| `app/.env.example` | те же имена переменных с пустыми значениями и комментариями | да |
| переменные в панели хостинга | настоящие ключи на проде | — |

🔴 **Сверяйте имена переменных буква в букву.** У нас `ACCEASS_CODE` вместо
`ACCESS_CODE` тихо отключил всю защиту доступа: программа такой переменной не видит,
ошибки нет, сайт просто открыт всем.

🔴 **Читайте `.env` своим кодом, а не флагом `node --env-file`.** Флаг есть не во всех
версиях Node, и из-за него проект «не запускается у другого человека». Готовая функция:

```js
import { readFileSync, existsSync } from "node:fs";

function loadEnv(file) {
  if (!existsSync(file)) return;
  for (const raw of readFileSync(file, "utf8").split("\n")) {
    const line = raw.trim();
    if (!line || line.startsWith("#")) continue;
    const eq = line.indexOf("=");
    if (eq < 1) continue;
    const key = line.slice(0, eq).trim();
    let val = line.slice(eq + 1).trim();
    if ((val.startsWith('"') && val.endsWith('"')) || (val.startsWith("'") && val.endsWith("'"))) {
      val = val.slice(1, -1);
    }
    if (process.env[key] === undefined) process.env[key] = val;  // среда важнее файла
  }
}

const here = dirname(fileURLToPath(import.meta.url));
loadEnv(join(here, ".env"));

// 🔴 Модули, читающие переменные при загрузке, импортировать ТОЛЬКО после loadEnv:
const { runStep } = await import("./agent.mjs");
```

## 4. Структура и стек

Проверенный выбор для небольшого продукта: **без сборки и без фреймворка.**
Ни Vite, ни React, ни Express. Причины прагматичные: нечему ломаться при деплое,
получатель проекта запускает двумя командами, ИИ не тратит шаги на конфиги сборки.

```
имя-проекта/
  index.js              точка входа для хостинга (см. ниже)
  package.json          корневой: scripts.start → node app/server.mjs
  .gitignore
  CLAUDE.md
  ПУБЛИКАЦИЯ.md         git + хостинг, всё в одном месте
  app/
    server.mjs          node:http: статика + API. Без Express
    agent.mjs           обращения к модели: схемы, промпты
    providers.mjs       слой провайдеров (основной + запасной)
    mock.mjs            демо-режим: записанный сценарий без обращения к модели
    test-flow.mjs       прогон всего сценария в jsdom, без сети
    .env / .env.example
    kb/                 база знаний: json + сборка в текст промпта
    public/             index.html, app.js, styles.css — без сборки
```

### Две точки входа — обязательно

🔴 Панель хостинга просит выбрать «тип приложения» из списка фреймворков и под каждый
подставляет свою команду запуска: чаще `node index.js`, иногда `npm start`. Сделайте
так, чтобы работали обе.

`index.js` в корне:

```js
// Точка входа для хостинга. Своей логики здесь нет и быть не должно.
import "./app/server.mjs";
```

Корневой `package.json`:

```json
{
  "name": "имя", "version": "0.1.0", "private": true, "type": "module",
  "scripts": { "start": "node app/server.mjs", "test": "node app/test-flow.mjs" },
  "dependencies": { "@anthropic-ai/sdk": "^0.70.0" },
  "engines": { "node": ">=18" }
}
```

## 5. Серверный каркас: обязательные куски

### Проверка живости `/healthz` — до всякой авторизации

🔴 Хостинг периодически пингует приложение. Если на пинг отвечать `401`, платформа
решит, что приложение упало, и уйдёт в перезапуск по кругу.

```js
const server = createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);

  if (url.pathname === "/healthz") {                 // ДО проверки доступа
    res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
    return res.end("ok");
  }

  res.setHeader("X-Robots-Tag", "noindex, nofollow, noarchive");
  if (url.pathname === "/robots.txt") {
    res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
    return res.end("User-agent: *\nDisallow: /\n");
  }
  // … дальше проверка доступа и маршруты
});
```

В настройках health check на хостинге указать **`/healthz`**, не `/`.

### Закрытие доступа кодом

Нужно всегда, когда наружу выставлено приложение с вашим ключом.

```js
import { timingSafeEqual } from "node:crypto";

const ACCESS_CODE = process.env.ACCESS_CODE || "";
const COOKIE = "pa_access";

function sameCode(v) {
  if (!v) return false;
  const a = Buffer.from(String(v)), b = Buffer.from(ACCESS_CODE);
  return a.length === b.length && timingSafeEqual(a, b);   // постоянное время
}

function authorized(req, url) {
  if (!ACCESS_CODE) return true;
  if (sameCode(url.searchParams.get("code"))) return true;       // ссылка ?code=…
  if (sameCode(cookieCode(req))) return true;                    // чтобы не спрашивать каждый раз
  const h = req.headers.authorization || "";
  if (h.startsWith("Basic ")) {                                  // для curl
    const [, pass = ""] = Buffer.from(h.slice(6), "base64").toString("utf8").split(":");
    if (sameCode(pass)) return true;
  }
  return false;
}
```

Вход по ссылке `?code=…` удобнее пароля: её можно просто переслать. После входа
код кладём в cookie и **убираем из адресной строки** редиректом, чтобы он не уехал
дальше с чьим-нибудь скриншотом.

🔴 **В заголовке `WWW-Authenticate` только ASCII.** Кириллица в значении HTTP-заголовка
невалидна, Node роняет ответ, а снаружи это выглядит как зависший запрос:

```js
"WWW-Authenticate": 'Basic realm="App name", charset="UTF-8"'   // без кириллицы
```

### Порт и устойчивость

```js
const PORT = Number(process.env.PORT || 5173);   // 🔴 на хостинге порт даёт платформа

// Одиночный сбой в запросе не должен ронять сервер во время демонстрации
process.on("uncaughtException", (e) => console.error("[uncaught]", e?.message || e));
process.on("unhandledRejection", (e) => console.error("[unhandled]", e?.message || e));
```

🔴 **`PORT` в панели хостинга не задавать вручную** — приложение сядет не на тот порт,
и снаружи это выглядит как «не отвечает».

### MIME-типы для статики

🔴 Забытый тип = картинки не отдаются. Минимальный набор:

```js
const MIME = {
  ".html": "text/html; charset=utf-8", ".js": "text/javascript; charset=utf-8",
  ".css": "text/css; charset=utf-8", ".json": "application/json; charset=utf-8",
  ".svg": "image/svg+xml", ".jpg": "image/jpeg", ".jpeg": "image/jpeg",
  ".png": "image/png", ".webp": "image/webp",
};
```

## 6. Работа с моделью

### Модель и формат ответа

Использовать актуальные модели Claude. На момент написания: `claude-opus-5`
(самая сильная), `claude-sonnet-5` (баланс, наш рабочий выбор), `claude-haiku-4-5`
(быстрая и дешёвая). SDK — `@anthropic-ai/sdk`.

**Структурированный вывод** вместо парсинга текста: модель обязана вернуть JSON
строго по схеме.

```js
const stream = client.messages.stream({
  model, max_tokens: maxTokens,
  thinking: { type: "adaptive" },                       // 🔴 не budget_tokens: на новых
                                                        // моделях его отклоняют с 400
  output_config: { effort, format: { type: "json_schema", schema } },
  system: cacheBreakpoint(system),
  messages: [{ role: "user", content: user }],
});
stream.on("thinking", (d) => onThinking?.(d));          // прогресс в интерфейс
const msg = await stream.finalMessage();
if (msg.stop_reason === "refusal") throw new Error("REFUSAL");
```

**Стримить** любой длинный ответ — иначе упрётесь в таймаут запроса.

### Кэширование промпта — главный рычаг цены

🔴 Системная часть промпта должна быть **байт-в-байт одинаковой** на всех шагах и
для всех пользователей. Тогда она кэшируется и повторно почти не оплачивается.
Инструкции конкретного шага — **в пользовательское сообщение**, не в системное:
иначе система меняется от шага к шагу и кэш не работает.

```js
const SYSTEM = [
  { text: KB,                   cache: true },   // база знаний целиком
  { text: ROLE + RULES,         cache: true },
];

/** Одна точка кэширования — на последнем блоке, помеченном cache. */
function cacheBreakpoint(blocks) {
  const last = blocks.map((b, i) => (b.cache ? i : -1)).filter(i => i >= 0).pop();
  return blocks.map((b, i) => ({ type: "text", text: b.text,
    ...(i === last ? { cache_control: { type: "ephemeral" } } : {}) }));
}
```

### База знаний: в промпт целиком или поиском?

Класть **целиком в промпт**, если она небольшая (ориентир: до ~10–15 тысяч токенов),
стабильная и модели полезно видеть всю картину сразу. Плюс она кэшируется.

Поиск по базе нужен, когда она не помещается или когда под каждый запрос нужен
маленький кусок из огромного объёма. Не усложняйте раньше времени.

### Запасной провайдер

Полезно иметь второй провайдер за тем же интерфейсом — на случай, когда основной
недоступен или дорог. Абстракция простая:

```js
// оба реализуют: run({ system, user, schema, maxTokens, effort, onThinking })
export function getProvider(id) { … }
export function pickProvider() { … }   // выбор по переменной PROVIDER=
```

🔴 У провайдеров без нативной поддержки схемы (OpenAI-совместимые) схему приходится
класть текстом в промпт, а ответ **проверять и один раз переспрашивать**. Отдельно
ловите обрыв по лимиту токенов: если рассуждение съело весь `max_tokens`, ответ
придёт пустым с `finish_reason: "length"` — повтор с тем же лимитом упрётся в ту же
стену, лимит надо поднять.

### Правила поведения в системном промпте

Что реально работает (из нашего опыта):

- запрет выдумывать факты: «опирайся только на базу знаний; если подходящего нет —
  оставь поле пустым, не сочиняй»;
- запрет на жаргон: «никаких англицизмов и узких терминов; если термин необходим —
  расшифруй его тут же в той же фразе»;
- запрет упоминать устройство инструмента: пользователь не должен видеть слова
  «база знаний», «схема», «поля»;
- 🔴 **числовые оценки надо якорить явно.** Модель склонна усреднять — тянуть
  оценку к середине шкалы. Если в тексте есть прямое утверждение («не могу
  отпустить контроль»), надо прямо написать: это значит крайнее положение, а не
  середина. Иначе получите благополучную картинку вместо реальной.

## 7. Тесты без браузера и без сети

Прогон всего пользовательского сценария в `jsdom` против записанных демо-данных.
Ловит опечатки в шаблонах и `undefined` в разметке до того, как их увидит человек.
Стоит копейки, окупается сразу.

```js
import { JSDOM } from "jsdom";
const dom = new JSDOM(html, { url: "http://localhost/", runScripts: "outside-only", pretendToBeVisual: true });
global.window = dom.window; global.document = dom.window.document;
global.fetch = fakeFetch;                    // заглушка: демо-данные вместо сети
new dom.window.Function(appJsCode)();        // запускаем фронтенд как есть
```

Полезные приёмы:

- считать обращения к API в заглушке — так можно доказать, что где-то модель
  **не** вызывается (например, при листании сохранённой записи);
- проверять, что в разметке нет строки `undefined` — ловит обращения к полям,
  которых нет;
- каждая проверка с человекочитаемым текстом: при падении сразу видно, что сломалось.

**Визуальная проверка без установки браузера.** Если на машине стоит Playwright,
внутри уже есть headless Chrome — им можно снимать скриншоты в нужной ширине:

```bash
CH=~/Library/Caches/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-mac-arm64/chrome-headless-shell
"$CH" --headless --disable-gpu --window-size=390,2000 \
      --screenshot=shot.png --virtual-time-budget=2000 "http://localhost:5173/"
```

🔴 Проверять вёрстку **скриншотом, а не на глаз по коду.** Мы так нашли, что
координатная плоскость на телефоне ужималась до 190 пикселей — по коду это было
незаметно.

## 8. Фронтенд без сборки

### Темы: три состояния, а не два

🔴 У темы три состояния: явно выбранная светлая, явно выбранная тёмная и «как в
системе» (никакого атрибута нет). Если цвет определён только внутри
`@media (prefers-color-scheme: dark)`, в третьем состоянии он не применится, и
получите текст одной темы на фоне другой.

```css
:root{ /* полная светлая палитра токенами */ }
@media (prefers-color-scheme:dark){
  :root:not([data-theme="light"]){ /* переопределяем ТОЛЬКО токены */ }
}
:root[data-theme="dark"]{ /* те же токены — чтобы переключатель побеждал */ }
```

`body` обязан задавать свой `background` токеном: прозрачный фон подхватит чужой.
Тему ставить до первой отрисовки, иначе мигает:

```html
<script>
  try { var t = localStorage.getItem("app.theme");
        if (t === "light" || t === "dark") document.documentElement.setAttribute("data-theme", t);
  } catch (e) {}
</script>
```

### Мобильные правила — в конец файла стилей

🔴 Медиазапросы **не добавляют специфичности**. Если мобильный блок стоит выше
описания компонента, обычное правило ниже его перебьёт, и часть правок просто не
сработает. Держите весь мобильный блок в самом конце.

Что проверить на телефоне обязательно:

- шапка не должна рассыпаться в кашу из переносов;
- цели нажатия: тонкий ползунок (5 px) и кружок «i» (15 px) пальцем не поймать —
  на сенсорных экранах расширять через `@media (pointer:coarse)`, можно невидимой
  зоной `::after { position:absolute; inset:-8px }`;
- 🔴 большой интерактивный блок с `touch-action: none` **съедает вертикальный
  свайп**, и страницу нельзя проскроллить мимо него. Ставьте `pan-y`, а
  непрерывное перетаскивание начинайте только с самого маркера;
- широкое содержимое (таблицы, схемы) — в контейнер с `overflow-x: auto`,
  страница вбок ездить не должна.

## 9. Публикация на Timeweb Cloud

**Облачные приложения → Создать → вкладка «Бэкенд» → Node.js.** Не «Фронтенд» и не
«Статический сайт»: приложение должно держать процесс.

| Поле | Значение |
|---|---|
| Тип | Бэкенд → **Node.js** |
| Фреймворк из списка | Express (или любой) — выбор лишь подставляет команды, мы их задаём сами |
| Версия Node.js | 20 или новее |
| Источник | GitHub → ваш репозиторий, ветка `main` |
| Директория | `./` |
| Команда сборки | `npm install` |
| Команда запуска | `npm start` |
| Порт | **не задавать** |
| Health check | `/healthz` |
| Автодеплой при push | включить |

Ресурсы: младший тариф (1 ядро / 1 ГБ) с запасом, если вся тяжёлая работа на стороне
модели. База данных, объектное хранилище, воркеры — не нужны, если приложение ничего
не хранит.

Переменные окружения задаются **в панели**, не файлом.

### Грабли Timeweb

🔴 **Платформа может выбрать не тот образ.** У нас она подставила `rust:1.95` для
Node-проекта, сборка падала на `npm install` с советом «используйте `cargo build`».
Никакого Rust в проекте не было. Лечится выбором правильного типа приложения
в панели, а не правкой кода.

🔴 **Исходящий доступ к API моделей из российского ЦОД может не работать.** TCP
проходит, TLS-рукопожатие отваливается по таймауту, при этом с ноутбука всё
работает. Это сеть, а не код — не переписывайте клиент. Лечится шлюзом-
ретранслятором: свой прокси (например, на Cloudflare Workers) и переменная
`*_BASE_URL`, указывающая на него.

### Порядок выкатки

1. Первый деплой **без переменных вообще** — приложение поднимется в демо-режиме.
   Убеждаемся, что сборка проходит и сайт открывается.
2. Потом `ACCESS_CODE` **и** ключ, вместе. Ключ без кода доступа выставлять нельзя.
3. Проверить:

```bash
curl -s -o /dev/null -w "healthz %{http_code}\n" https://адрес/healthz   # 200
curl -s -o /dev/null -w "корень  %{http_code}\n" https://адрес/          # 401 при коде
curl -s https://адрес/robots.txt                                          # Disallow: /
```

4. Открыть `https://адрес/?code=КОД` и пройти сценарий целиком. Курл говорит только
   «сервер отвечает», он не говорит, что продукт работает.

## 10. Дать другим потыкать

**Ссылка на свою машину** (быстро, живёт пока открыто окно):

```bash
npx --yes localtunnel --port 5173
```

🔴 `cloudflared` у нас не заработал: TLS-рукопожатие отваливалось и по QUIC, и по
HTTP/2 — сеть резала сам протокол туннеля. `localtunnel` работает поверх обычного
HTTPS и проходит там, где cloudflared не проходит. Перед раздачей ссылки обязательно
задайте `ACCESS_CODE`.

**Архивом** — если у человека должно работать локально. Кладите `node_modules` мимо
архива (получатель поставит сам), и делайте два варианта: без ключей и с ключами.
Вариант без ключей должен **проверять сам себя** и отказываться собираться, если
`.env` в него попал.

## 11. Работа с ИИ: что экономит время

- 🔴 **Фоновые процессы.** Сервер, запущенный ИИ в фоне, между ходами разговора
  может быть убит средой. Для устойчивости — `nohup … & disown`; а лучше
  запускайте сервер сами в своём терминале, тогда он живёт независимо.
- **Не «сделай красиво», а «сделай и покажи».** Просите скриншот или прогон теста.
  Иначе легко получить «готово» там, где ничего не проверено.
- **Правки промпта проверяйте вживую.** Тесты ловят вёрстку и опечатки, но не
  качество ответов модели. После правки промпта прогоняйте реальный сценарий.
- **Спорные развилки** выносите на отдельного советника со свежим взглядом, потом
  решайте сами.
- 🔴 **Русские имена файлов в zip.** `unzip` на macOS ломает кириллицу —
  распаковывайте Python-ом:

```bash
python3 -c "
import zipfile, os
z = zipfile.ZipFile('архив.zip')
for i in z.infolist():
    if i.is_dir(): continue
    p = os.path.join('archive', i.filename)
    os.makedirs(os.path.dirname(p), exist_ok=True)
    open(p,'wb').write(z.read(i))
"
```

- **Картинки из документов** достаются без конвертеров: `.docx` и `.pptx` — это zip,
  внутри `word/media/` и `ppt/media/`.
